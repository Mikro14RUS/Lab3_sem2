# Лабораторная работа №3 — Go

Многофайловая реализация тех же структур данных на Go: массив, односвязный
и двусвязный списки, стек, очередь, хеш-таблица и Full Binary Tree.
Консольного приложения нет; сериализация структур выполнена в текстовом
JSON-формате (`SaveText`/`LoadText`) и бинарном формате
(`SaveBinary`/`LoadBinary`) пакета `containers`.

## Состав

```text
internal/containers/   структуры, JSON- и бинарная сериализация, тесты
```

## Проверки

```bash
go test ./... -cover
go test ./... -coverprofile=coverage.out
go tool cover -html=coverage.out -o coverage.html
go test -v ./internal/containers -run 'Binary'
go test ./... -run '^$' -bench=. -benchmem
go vet ./...
gofmt -l .
```

Тесты используют стандартный `testing` и `testify` (`assert`/`require`).
Зависимость зафиксирована в `go.mod` и `go.sum`; при первом запуске Go
скачает testify и его транзитивные зависимости.

## Формат текстовой сериализации

`SaveText` записывает JSON-конверт с сигнатурой `DS3TXT`, версией, типом и
именем каждой структуры, а также её `payload`. `LoadText` проверяет сигнатуру,
версию, уникальность имён и восстанавливает конкретный тип по полю `type`.

## Формат бинарной сериализации

`SaveBinary` создаёт файл с сигнатурой `DS3BIN`, версией `1` и количеством
записей. Каждая запись содержит тип, имя и длину payload, после чего идёт
бинарный payload с тем же тегом структуры, что и в C++-версии:

- `ARR1`, `LST1`, `DLST`, `STK1`, `QUE1` — количество строк и строки
  «длина + байты UTF-8»;
- `HSH1` — количество пар и пары «ключ — значение»;
- `TRE1` — preorder-обход с маркерами отсутствующих детей и 32-битными
  значениями.

Все числа записываются в little-endian. `LoadBinary` проверяет сигнатуру,
версию, границы размеров, уникальность имён, теги payload и корректность
preorder-формата дерева.
